# ARCHITECTURE.md: Sonoran Swap

> How the code is organized, which services we use, and how data flows. Requirements live in `docs/SRS.md`; this file says **where** and **how** to build them.

## 1. Stack (chosen for speed, reliability and Lighthouse scores)

| Layer | Choice | Why | Alternative if blocked |
|---|---|---|---|
| Framework | **Next.js (latest stable, App Router)**, React, TypeScript strict | SSG for marketing pages, route handlers for APIs, `next/image`, `next/font`, metadata API | — |
| Package manager | **pnpm** | Fast, strict | npm |
| Styling | **Tailwind CSS** (latest) + CSS variables from `DESIGN_SYSTEM.md` | Fast, consistent tokens | — |
| Components | **shadcn/ui** (Radix primitives), restyled | Accessible behavior out of the box | Radix directly |
| Motion | **Framer Motion** (sparingly) or CSS transitions | Reduced-motion support | CSS only |
| Content | JSON in `content/` + **MDX** guides (`@next/mdx` or `next-mdx-remote`) | Non-devs can edit; validated at build | — |
| Validation | **Zod** | One schema for API + content | — |
| Database | **Postgres on Neon, Free plan** (via Vercel Marketplace) | $0, one-click env vars, serverless driver | Supabase Free plan |
| ORM | **Drizzle ORM** + drizzle-kit | Typed, light, SQL-like | Prisma |
| Maps | **Mapbox GL JS** (satellite style) + **@mapbox/mapbox-gl-draw** + **@turf/area** + Mapbox temporary geocoding, on the **no-credit-card trial** (5,000 GL JS map loads and 10,000 temporary geocoding requests per month) | $0; satellite imagery, drawing, accurate area. Over the cap the map stops loading, which the manual and sample paths already cover (FR-EST-13) | MapLibre + another satellite source on a free, no-card plan (check its terms and attribution) |
| AI images | **Provider adapter** with three $0 tiers: (1) **curated gallery** of renders made ahead of time for free (always works); (2) **live edit via a free API key** if one passes the Phase 0 spike: a Google AI Studio (Gemini) key without billing, or Cloudflare Workers AI's free daily allocation if its catalog has an image-to-image model; (3) `mock` for tests | $0 guaranteed by tier 1; live edits are a bonus | Gallery-only mode |
| Push | **ntfy** (hosted ntfy.sh or self-host) | One HTTP POST, instant phone push, no carrier registration | Pushover |
| Email fallback | **None by default** (optional: a free email API tier, no card) | Fewer accounts; push plus the on-screen preview is enough for the demo | — |
| Rate limiting | **Postgres table** (`rate_limits`: ip_hash, window, count) | $0, no extra account | Upstash free plan |
| Analytics | **Vercel Analytics** (cookieless) + first-party `events` table | Page views + funnel | Plausible |
| Testing | **Vitest**, Testing Library, **Playwright**, **@axe-core/playwright** | Unit, e2e, accessibility | — |
| QR | `qrcode` (client) | /live board | — |
| Hosting | **Vercel Hobby (free)** (production = `main`) on the free `*.vercel.app` URL; a custom domain only if one is free to the team | Previews per PR, edge OG images | Netlify free / Cloudflare Pages free |

> **$0 rule:** never add a credit card or payment method to any account. Free plans then pause or reject requests at their limits instead of billing, and every feature has a free fallback. See §11.
>
> Model names, map styles and API endpoints change. Agents must confirm current names in provider docs at build time and keep them in env vars, never in code.

## 3. Rendering strategy

| Route type | Strategy |
|---|---|
| Marketing and content pages (/, /rebates/*, /styles/*, /plants, /pricing, /how-it-works, /guides/*, /privacy, /accessibility) | Static (SSG) from `content/`; client islands only for interactive parts (QuickEstimate, slider, accordion) |
| /studio, /visualize, /eligibility, /book | Static shell + client components; heavy modules (`mapbox-gl`, draw, visualizer) via `next/dynamic` with `ssr: false` and reserved dimensions |
| /book/confirmed/[id] | Dynamic server component reading the booking |
| /launch-notes | Static with a client tab for live testing numbers |
| /live | Client page polling `/api/stats` |
| /api/* | Node runtime route handlers (OG on edge) |

## 4. Data flow

### 4.1 Estimate
```
Browser: address → Mapbox geocode (browser only) → map fly-to
       → user draws polygons → turf area (m²→sq ft) → engine.computeRebate (instant UI)
       → POST /api/estimates {city, sqft, source, tier, ...}   (no address, no coordinates)
Server: Zod validate → engine recompute → pricing + water → insert estimates → return {id, ...}
```

### 4.2 Render
```
Browser: file → orientation fix, resize ≤1536px, JPEG 0.85, strip EXIF → POST /api/render (multipart)
Server: validate type/size → rate limit (IP hash) + daily cap → prompt.build(style)
       → ImageProvider.edit(imageBuffer, prompt, {timeoutMs: 50000})
       → returns bytes → base64 to client; insert renders(metadata only); never persist the image
Fallback: any error/timeout/MOCK → client shows /public/samples/<style>-after.jpg with "Example rendering" label
```

### 4.3 Booking
```
Browser: slot + city (+ estimateId) + idempotencyKey → POST /api/bookings
Server: validate → slots.isAvailable → insert → notify (ntfy; on failure mark not delivered) → update notified → {id}
Browser: → /book/confirmed/[id]
```

### 4.4 Stats, live board and insights
```
/api/stats?since → aggregate queries (counts, sums, by city, last 8 estimates, testing metrics) → cache 5 s
/live polls every 5 s; Proof drawer fetches once on open
/api/insights?since → unique-session funnel, CTR by variant, sources, audience, health (team sessions excluded) → cache 30 s
/insights renders panels + content/decisions.json + content/seo-report.json
```

## 5. Content pipeline
- `lib/content/load.ts` imports JSON at build time, validates with Zod, and exports typed objects. A schema error fails `pnpm build`.
- Guides are MDX with validated frontmatter.
- `content/timeline.json` is produced by `scripts/timeline.ts` from `git log --date=iso --pretty=...` filtered to `feat|fix|perf|docs(content)` commits; committed to the repo because Vercel builds use shallow clones.

## 6. Provider adapters

```ts
// lib/ai/image-provider.ts
export interface ImageProvider {
  name: string;
  edit(input: { image: Buffer; mime: "image/jpeg"; prompt: string; signal: AbortSignal }): Promise<{ image: Buffer; mime: string }>;
}
export function getImageProvider(): ImageProvider  // by env IMAGE_PROVIDER = gallery | gemini | cloudflare | mock
```
- Each provider maps its errors to `PROVIDER_REFUSED | PROVIDER_TIMEOUT | PROVIDER_ERROR`.
- `mock` returns the style's sample after-image after a 1.5 s delay (used in tests and `?demo=1`).
- `gallery` returns the closest pre-rendered result for the chosen style and is the $0 default if no free live provider passes the spike.
- Every live provider honors `RENDER_DAILY_CAP` so free quotas are never exceeded; at the cap, the route serves the gallery result with the fallback label.
- Notifications use the same pattern: `Notifier` with `ntfy`, `mock`.

## 8. Deployment and environments
- **Production:** `main` → Vercel production → `*.vercel.app` (or a free custom domain). Must never require login (disable Vercel Deployment Protection for production).
- **Preview:** every PR gets a preview URL (protection may stay on for previews).
- **Database:** one Neon database; migrations run via `pnpm db:migrate` locally against `DATABASE_URL` before merging schema changes.
- **CI (GitHub Actions):** on PR: install, typecheck, lint, unit tests, `next build`, and a grep that fails if any server secret name appears in client bundles.
- **Demo mode:** `?demo=1` sets a client flag that routes render and notify calls to mocks (server honors header `x-demo: 1` only for those two routes), and preloads sample assets so the core flow works if Wi-Fi drops after first load.

## 9. Security notes
- Security headers in `next.config` (`headers()`): CSP, HSTS, nosniff, referrer policy, frame-ancestors none.
- Route handlers enforce body size limits (render 5 MB, others 32 KB).
- No user-generated HTML is rendered. MDX only from the repo.
- Mapbox token restricted to production and preview domains in the Mapbox dashboard.
